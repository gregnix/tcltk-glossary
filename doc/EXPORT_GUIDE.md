# Export guide

How to export, edit, re-import the glossary using the
command-line tools under `tools/`.

## Overview

| Tool                              | Purpose                                  |
|-----------------------------------|------------------------------------------|
| `export_index.tcl`                | Categories overview with sample terms    |
| `export_category.tcl`             | One category, full content               |
| `export_full.tcl`                 | Complete glossary as Markdown            |
| `export_full.tcl --for-docir`     | docir-pipeline-friendly Markdown         |
| `glossary_to_pdf.tcl`             | Markdown → PDF (with TOC and index)      |
| `import_md.tcl`                   | Markdown → SQLite (additive)             |

All export tools write to stdout. Redirect to a file with `>`.

## Edit-cycle workflow

The recommended way to make substantial changes is to work in
Markdown and re-import. The GUI is good for one-off edits; for
revising a whole category, Markdown is faster.

### Step 1: export the index

```bash
tclsh tools/export_index.tcl glossary.db > index.md
```

`index.md` is a one-page overview: per category, the term count and
three sample terms. Use it to scope your work.

### Step 2: list the category names

The categories are visible in `index.md`. To get just the names:

```bash
sqlite3 glossary.db \
    "SELECT DISTINCT category, COUNT(*) FROM terms
     GROUP BY category ORDER BY category;"
```

### Step 3: export the category you want to edit

```bash
tclsh tools/export_category.tcl glossary.db "TclOO" > tcloo.md
```

Wildcards are SQL LIKE patterns:

```bash
tclsh tools/export_category.tcl glossary.db "Widget*" > widgets.md
```

### Step 4: edit `tcloo.md` in your editor

Add new terms in the same Markdown format. Modify existing terms
(this is what you want to be careful about — see "Re-import
behaviour" below).

### Step 5: re-import

```bash
tclsh tools/import_md.tcl tcloo.md glossary.db
```

The import is **additive**: existing terms are skipped with a
`SKIP (duplicate)` message. To update an existing term, you have
two options:

- Use the GUI edit dialog (`Ctrl+E`)
- Delete the term first
  (`sqlite3 glossary.db "DELETE FROM terms WHERE term='X';"`)
  and re-import

### Step 6: verify in the GUI

```bash
wish glossary_gui.tcl glossary.db
```

## Examples

### Overview for a code review

```bash
tclsh tools/export_index.tcl glossary.db > index.md
# Send index.md to a reviewer; it's roughly 100 lines, easy to read.
```

### Review the TclOO category

```bash
tclsh tools/export_category.tcl glossary.db "TclOO" > tcloo.md
# Edit/comment in tcloo.md, send back, then re-import.
```

### All widget-related categories

```bash
tclsh tools/export_category.tcl glossary.db "Widget*" > widgets.md
# tcl-LIKE pattern; both "Widgets" and "Widget Properties" match.
```

### Find small categories first

The smallest categories are usually the easiest to revise
completely:

```bash
sqlite3 glossary.db \
    "SELECT category, COUNT(*) FROM terms
     GROUP BY category ORDER BY COUNT(*) ASC LIMIT 5;"
```

## Useful SQL queries

Run via `sqlite3 glossary.db`. Or via the GUI's search field for
the FTS5-friendly ones.

### Terms with empty fields

```sql
SELECT term, category FROM terms
WHERE en_definition = '' OR de_definition = ''
ORDER BY category, term;
```

### Terms without examples

```sql
SELECT term FROM terms
WHERE (en_example IS NULL OR en_example = '')
  AND (de_example IS NULL OR de_example = '');
```

### Top-10 largest categories

```sql
SELECT category, COUNT(*) AS n
FROM terms GROUP BY category
ORDER BY n DESC LIMIT 10;
```

### Smallest categories

```sql
SELECT category, COUNT(*) AS n
FROM terms GROUP BY category
ORDER BY n ASC LIMIT 10;
```

### Terms with TODO/FIXME notes

```sql
SELECT term, category, notes FROM terms
WHERE notes LIKE '%TODO%' OR notes LIKE '%FIXME%';
```

## Re-import behaviour

`tools/import_md.tcl` is **additive only**. The check is on the
`term` column (which is `UNIQUE`):

- New term name → row inserted
- Existing term name → row skipped (no overwrite, no merge)

Reasons:

- Predictable: re-importing the same file twice is idempotent.
- Safe: there's no way to accidentally clobber edited content.
- Simple: no merge logic, no conflict handling.

Trade-off:

- For updates, use the GUI or `DELETE + import`.

## Producing a PDF

```bash
# Step 1: docir-friendly Markdown
tclsh tools/export_full.tcl glossary.db --for-docir > all.md

# Step 2: render to PDF
tclsh tools/glossary_to_pdf.tcl all.md glossary.pdf
```

The PDF is generated by the docir / mdstack / pdf4tcl pipeline. It
includes a TOC, an alphabetical term index, and PDF bookmarks.
Approximately 150 pages for the bundled 1324 terms.

## Tips

### Always treat Markdown as the source of truth

The database is a derived view. If you make a change in the GUI,
also update the Markdown master if you maintain one. Otherwise
the master diverges and re-importing it would re-create old
versions of edited terms (which the additive import then
skips — but the discrepancy is hidden).

### Smaller categories first

When revising the whole glossary, start with categories that have
< 20 terms. They are easier to review in one sitting and the
diffs are easier to follow.

### Incremental work

Commit each category as a separate commit (or PR). If a later
edit introduces a regression, bisecting per category is much
faster than bisecting per line in a single big diff.

### Git ignores the binary database

`glossary.db` is binary; git diffs on it aren't useful. The
recommended workflow is:

- track the Markdown master in git
- regenerate the database from Markdown periodically
  (`tools/import_md.tcl` against an empty schema)
- treat the in-repo `glossary.db` as a build artefact (it is
  shipped for convenience, but rebuildable)

In this repository the database is committed for convenience
(users get a working glossary immediately), but if you fork and
maintain your own, consider using `.gitignore`.
